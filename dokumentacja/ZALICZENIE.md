# Zaliczenie Wymagań Projektowych

## Wymagania minimalne

| ID     | Wymaganie            | Opis realizacji w projekcie                                                                                                                                                                                                                                       | Status         |
| :----- | :------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------- |
| **R1** | **Backend API**      | REST API w **Go** i frameworku **Echo**. Aplikacja wystawia 3 zasoby: `Users` (użytkownicy), `Trails` (szlaki górskie) oraz `Favorites` (ulubione szlaki z relacją do użytkownika).                                                                               | ✓ Zrealizowano |
| **R2** | **Baza danych**      | Persystentna, relacyjna baza **PostgreSQL** z rozszerzeniem **PostGIS** do przechowywania danych przestrzennych (geometria szlaków). Wersjonowanie schematu i migracje (`.up.sql`, `.down.sql`) zarządzane są za pomocą natywnego narzędzia **golang-migrate**.   | ✓ Zrealizowano |
| **R3** | **Frontend**         | Interfejs użytkownika to dynamiczne Single Page Application stworzone w **React** (Vite). Do stylizacji użyłem **Tailwind CSS**, a renderowanie interaktywnej mapy z API bazuje na technologii **MapTiler** (wektorowe kafelki mapowe).                           | ✓ Zrealizowano |
| **R4** | **Autentykacja**     | Bezpieczny mechanizm logowania i autoryzacji oparty na tokenach **JWT** (JSON Web Token). Hashowanie haseł odbywa się za pomocą algorytmu **bcrypt**. Zarządzanie ulubionymi szlakami (`/api/favorites`) jest chronione middlewarem.                              | ✓ Zrealizowano |
| **R5** | **Konteneryzacja**   | Cały system jest w pełni skonteneryzowany. Za pomocą pliku `docker-compose.yml` można jedną komendą (`docker-compose up --build -d`) podnieść bazę danych (obraz z PostGIS), backend napisany w Go oraz frontend w React.                                         | ✓ Zrealizowano |
| **R6** | **Repozytorium**     | Projekt znajduje się w publicznym repozytorium na GitHub. W głównym pliku `README.md` znajduje się instrukcja uruchomienia a w folderze dokumentacja razem z rejestrem decyzji architektonicznych (ADR) z uzasadnieniem technologicznym.                                    | ✓ Zrealizowano |

## Elementy dodatkowe

| Element               | Opis realizacji w projekcie                                                                                                                                                                                                                                                                                                                                   | Status         |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------- |
| **Walidacja danych**  | (Schema validation) na wejściu API za pomocą biblioteki przez `go-playground/validator`. Walidator używa deklaratywnych tagów przy strukturach DTO, chroniąc system m.in. przed niepoprawnym parametrami (np. ujemne ID z query params) i dbając o złożoność haseł użytkowników (minimum 8 znaków, wielka/mała litera, cyfra, znak specjalny).                | ✓ Zrealizowano |
| **Cache**             | Zastosowałem manualny chache przez wzorzec proxy do bazy danych, w którym zapytania o najczęściej pobierane zasoby są buforowane. Pozwala to na znaczące odciążenie głównej instancji PostgreSQL oraz ograniczenie zapytań do zewnętrznych API.                                                                                                               | ✓ Zrealizowano |
| **Seed data**         | System automatycznie ładuje początkowe dane o szlakach z pliku `trails.csv` jeżeli tabela trails jest pusta w bazie danych. Zapewnia to prostą kontrolę nad aktualizacją szlaków (np. zmiana koloru) lub dodaniu nowego regionu (append pliku CSV). Na potrzeby demonstracyjne ładowane są też dane dwóch userów Test1 i Test2 każdy z hasłem `Password123!`. | ✓ Zrealizowano |
